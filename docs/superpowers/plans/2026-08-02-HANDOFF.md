## What just got fixed (done, verified)

**Reactions and replies were refused forever in any community pulled from the
anchor.** `profile.sync_inventory` is a cache of the active namespace's live
set; an anchor pull imports entries into the store without touching it, and
`ensure_complete_sync_inventory` treated the divergence as fatal
(`MobileError::Internal`). Swift maps `.Internal` into the authority bucket, so
a cache-coherence bug was shown to people as "Reactions aren't available for
this post" / "That reply was not accepted".

Fixed in `mobile_state.rs` by rebuilding the inventory from the store's signed
entries (`rebuild_sync_inventory`) instead of failing closed. Red verified by
reverting the fix — fails with the exact field error. Commit `22c2be7a`.

**The app has NOT been rebuilt against this.** The staticlib and bindings must
move together or you get a UniFFI checksum abort at launch. Do this first and
confirm the bug is actually gone on the macOS build:

```
cargo build --locked -p riot-ffi --lib --release --features net --target aarch64-apple-darwin
cp target/aarch64-apple-darwin/release/libriot_ffi.a build/native/macos/libriot_ffi.a
cd apps/macos && xcodebuild -project Riot.xcodeproj -scheme Riot-macOS -configuration Debug -destination 'platform=macOS' build
```

## Next two pieces of work

### 1. Can an author withdraw their own words? (decision, then code)

A `#[ignore]`d RED test records the requirement:
`newswire_contract.rs::an_author_can_retract_their_own_reply_without_an_editorial_role`
— currently fails with `InvalidInput`.

`create_signed_editorial_action(author, descriptor, action)` takes **no store
handle**, so it cannot check who wrote the target entry. Enabling this means
either threading the target's authorship into the core, or gating it in the FFI
where the store is reachable. **Ask the owner first** — it changes who may
mutate what. My view: an author obviously has standing over their own record,
but it should be decided, not slipped in to make a test pass.

`Retract`, `Correct`, `Tombstone` all exist in `NewswireEditorialActionKind`
and have no UI at all. Surfacing them is separate work again.

### 2. Push to anchor — the missing half of the loop

`sync_with_anchor` is **pull only**. There is no push from a phone. So a reply
written today is saved correctly and then never leaves the device except over
nearby BLE / local network to someone in the room.

The relay already accepts `PrepareHost → push → CommitHost` from a host; the
phone needs to hand its signed entries up the same way. This is more contained
than peer-to-peer, because a relay is a stable always-on NodeId rather than a
backgrounded phone.

## Standing context worth not rediscovering

- **`/usr/bin/log`, never `log`** — zsh has a builtin `log` that silently
  swallows every query. This cost a day; it looked like the app emitted nothing.
- **Keychain access is per code signature.** Alternating a Developer-ID DMG with
  an ad-hoc Debug build gives different keys, the sealed identity won't open,
  and the profile is quarantined. It looks exactly like upgrades destroying user
  data. Run `codesign -dvv` on every bundle you launched before believing it.
  Two plan docs were written on that misreading before it was caught.
- **Tests substitute what breaks.** `open_local_profile()` is in-memory, the
  older Swift tests pass no `databasePath`, and `ReactionUITestFixture` is "a
  bounded IN-MEMORY wire" with a "stable IN-MEMORY wrapping key". That is how
  303 Rust and 546 Swift tests stayed green while every interaction was broken.
  New tests go on the real substrate — `DurableJourneyTests.swift` is the model.
- **6 Swift tests are red on main already** (AnchorProtocolVector,
  CompactReactionBar, NewswireSurface, ShellNavigation). Pre-existing; verified
  identical on a clean `origin/main` worktree. Not yours.
- Fresh worktree needs `build/native/ios-simulator/libriot_ffi.a`, and on Apple
  Silicon that slice must be **`aarch64-apple-ios-macabi`** (Mac Catalyst), not
  `aarch64-apple-ios-sim`.

## The honest state

A person can create a community, post, reply, react, and come back to it later
on one device. As of today they can also contribute to a community pulled from
a relay. They cannot correct what they wrote, and nothing they write reaches
anyone who is not in the same room.
